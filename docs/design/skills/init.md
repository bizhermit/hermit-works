# hw:init 設計書

`hw:init`は、本プラグインが前提とする規律の節と設定ファイルを利用者環境へ展開する。動作の仕様は[SKILL.md](../../../plugin/skills/init/SKILL.md)を正本とし、本書はそこからだけでは読み取れない箇所を補う。

## 使用範囲とgitの扱い

`project`は、規律をチーム標準としてリポジトリで共有する場合に選ぶ。展開先は`CLAUDE.md`であり、`.hw/settings.json`がgit管理下に入る。展開先・`.gitignore`・`.hw/settings.json`のコミットは利用者が行う。

`project`であっても、`.hw/cases/`と`.hw/plans/`はgit管理外のままである。進行記録は個人の作業ファイルとして扱う。共有したい場合は`.gitignore`を手で調整すればできるが、推奨しない。

`local`は、個人利用でgit管理外に置く場合に選ぶ。展開先は`CLAUDE.local.md`であり、`.hw/`配下は一律にgit管理外となる。`.gitignore`は`.git/info/exclude`より優先されるため、`.gitignore`に否定パターンが残っている限り`.git/info/exclude`側では打ち消せない。`hw:init`は`.gitignore`から否定パターンを除くことでこれを成立させる。

`local`を選んだ場合も、`.gitignore`はリポジトリで共有されるファイルである。追記・除去された行をコミットするかどうかは利用者が決める。

## `.gitignore`の`.hw`関連行は`hw:init`が組み直す

gitのignoreは最後に一致したパターンが勝つため、`.hw/*`より前に`!.hw/settings.json`があると追跡されない。`hw:init`は`.hw`に関する行をひとまとまりとして扱い、`.hw/*`が否定パターンより必ず前に来るよう毎回組み直す。既存の行の位置は動く。

利用者が`project`で追跡対象を増やすために書いた`!.hw/`から始まる行は残り、`common`の内容の下へまとめられる。`local`ではこれらの行は落ちる。個人利用では`.hw/`配下を一律に共有しないためであり、`local`のあいだは追跡対象を増やせない。

否定でない`.hw`行（`.hw/`や`.hw/tmp/`など）は捨てられる。`common`の`.hw/*`が`.hw`直下のすべてを除外するため効果が重複しており、とくにディレクトリ形式の`.hw/`が残っていると`.hw`ディレクトリ自体が除外され、`project`でも否定パターンが原理的に効かなくなるためである。

## `.hw/settings.json`が壊れていても止まらない

`.hw/settings.json`が読めない、または`version`か`scope`が欠けている場合、`hw:init`は中断せず初回実行として進み、手順8でファイルを書き直す。記録として使えないものを残す意味がないためである。

初回実行として進むが、展開先の節が上書きされることはない。展開先に節があれば内容を比較して維持し、上書きは指示を受けたときだけ行う。

ただし直前の使用範囲が分からなくなるため、次の2つが起こらない。`project`から`local`へ切り替えても、`CLAUDE.md`にある節は`CLAUDE.local.md`へ移らない。展開先でない方に残った節も除去されない。使用範囲を移したい場合は、実行後に節を手で移すか、正しい`.hw/settings.json`が書かれた状態で改めて`hw:init`を実行する。

## gitリポジトリでない場合

プロジェクトルートはgitのリポジトリルートだが、gitリポジトリでない場合はセッションの作業ディレクトリになる。立ち上がりでまだgit管理していないプロジェクトを想定した扱いであり、次の2点に注意する。

起動場所によって展開先が変わる。別のディレクトリから実行すると初回実行と判定され、2つ目の`.hw/`と展開先ができる。同じ場所から実行する。

git管理を始めると、以後はリポジトリルートが基準になる。それまでの展開先がリポジトリルートと違う場所であれば、次の実行は初回実行として扱われる。展開物と`.hw/`はリポジトリルートへ移す。

なお`.gitignore`の整備（手順6）はgitリポジトリでなければ行われない。`local`を選んでも`.hw/`配下はgitの管理外になっていないため、git管理を始めた時点で`hw:init`を実行し直す。
