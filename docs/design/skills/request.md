# hw:request

依頼元の要望を、引数と対話を通して言語化し、指示書として残す。手順の定めは[SKILL.md](../../../plugin/skills/request/SKILL.md)にあり、本書はその処理フローを図で示す。

## 手順の処理フロー

図の読み方：

- 平行四辺形は依頼元との対話（問いと答え）である。答えを得るたびに依頼原文へ追記してから次へ進む
- いずれの問いでも、答えまたは承認が得られなければ、問いを示したまま停止する。推測で補って進めない

```mermaid
flowchart TD
    S([開始]) --> A1["引数を読む"]
    A1 --> A2{"引数があるか"}
    A2 -- ない --> A3[/"要望を問う"/]
    A3 --> B1
    A2 -- ある --> B1["現物を指す語をリポジトリまたは依頼元が示す所在で確かめる"]
    B1 --> B2{"実在し一意か"}
    B2 -- 見つからない／複数 --> B3[/"判断を求める問い"/]
    B3 --> B1
    B2 -- 一意 --> C1["雛形の節ごとに依頼原文で満たされるか確かめる"]
    C1 --> C2{"満たされない節があるか"}
    C2 -- ある --> C3[/"意向を聞く問い（一件）"/]
    C3 --> C1
    C2 -- ない --> D1["出力先を決める（指定、運用、既定の順）"]
    D1 --> D2{"所在が定まるか"}
    D2 -- 定まらない --> D3[/"判断を求める問い"/]
    D3 --> D1
    D2 -- 定まる --> E1[/"草案と出力先を示し、承認を問う"/]
    E1 --> E2{"承認か"}
    E2 -- 修正あり --> E3["修正を反映"]
    E3 --> E1
    E2 -- 承認 --> F1["出力先へ出力"]
    F1 --> F2{"成功か"}
    F2 -- 失敗 --> X1(["停止：失敗の内容と指示書の本文を示す"])
    F2 -- 成功 --> F3["URLまたはパスを報告"]
    F3 --> T([終了])
```

### 判断を求める問い

図中の「判断を求める問い」は、三段の対話で進める。

```mermaid
flowchart TD
    P1[/"第1段：課題（問題と影響範囲、原因）を示し、意見を聞く"/]
    P1 --> P2[/"第2段：意向を汲んで方針を言語化し、合っているか確かめる"/]
    P2 --> P3{"合っているか"}
    P3 -- 違う --> P2
    P3 -- 合っている --> P4{"方針が手段まで定めているか"}
    P4 -- 定めている --> P5["確かめた答えを判断とし、第3段を省いた理由を依頼原文に記す"]
    P4 -- 定めていない --> P6[/"第3段：複数の案、利害得失、推奨と根拠を示し、判断を受ける"/]
    P6 --> P7{"推奨と逆の案で、矛盾があるか"}
    P7 -- ある --> P8[/"一度だけ指摘する"/]
    P8 --> P9["維持されたら従う"]
    P7 -- ない --> P9
```
