# hw:execute

指示書（`hw:request`が作成したもの、または`hw:request`以外の手段で書かれたもの）を受け、対応方針を立てて依頼元の承認を得たうえで、実行計画を立て、計画のタスクごとに実行者に実施させ、評価者のレビューを経て成果物を仕上げる。手順は[SKILL.md](../../../plugin/skills/execute/SKILL.md)に定めてあり、本書はその処理フローを図で示す。

## 手順の処理フロー

### 図の読み方

- 平行四辺形は、依頼元との対話（問いと答え、承認）を表す
- 二重枠は、担当（サブエージェント）を起動することを表す。実行者は`hw:worker`、評価者は`hw:reviewer`である

### 図とあわせて読む規則

- 依頼元との対話で得た答えは、`plan.md`の「裁定」の節に書く
- 担当は起動するたびに別の人物になる。統括（本スキルを実施する人物）は、作業に要るもの（作業、目的、完了条件、制約、変えてよい範囲、読む資料、記録の形、書き先、返答の形）をプロンプトに書いて渡す。担当は記録を書き先（`worker-<n>`、`reviewer-<n>`）に書き、返答は一行だけを返す。統括は返答を見て次に何をするかを決め、記録は要る節だけを、見出しを手がかりに抜き出して読む
- いずれの問いでも、答えまたは承認が得られなければ、問いを示したまま停止する
- 担当の起動に失敗したら、または返答のパスに記録が無ければ、失敗の内容（コマンドと応答）を示して停止する。統括が代わりに作業しない
- 統括が行ったこと（問いと答え、対応方針の承認、担当の起動、報告の受領、判定、状態の変更）は、その都度`plan.md`の「経過」の節に書く
- 指示書に完了条件が無くても停止しない。完了条件は統括が指示書から割り出し、統括が割り出したものと分かる形で「対応方針」の節に書き、依頼元が対応方針を承認するときに確かめる
- 変えてよいのは、指示書の制約の内で、計画の変えてよい範囲に書いた場所だけである。指示書の対象範囲や依頼元の意見は、対応方針で変更の対象を定めるときの材料である
- 計画については依頼元に承認を問わない。計画を変える（タスクの追加、削除、完了条件や範囲の変更）とき、対応方針も変わるなら、変えた対応方針を依頼元に示して承認を得る。対応方針が変わらなければ、変えた内容を「経過」の節に書いて進む

### 全体の流れ

```mermaid
flowchart TD
    S([開始]) --> A1["指示書を読み、案件ディレクトリを作り、instruction.mdに写す"]
    A1 --> A2{"目的があるか"}
    A2 -- ない --> X1(["停止：hw:requestで補うよう示す"])
    A2 -- ある --> B1[/"指示書の未確定事項と、依頼元にしか決められない事項を一件ずつ問う"/]
    B1 --> P1["plan.mdの「対応方針」の節を書く（未確定事項の裁定、完了条件と確かめ方（指示書に完了条件が無ければ統括が割り出す）、変更の対象、作業の場所と終点、指示書に無い要件、検証の資源・権限・副作用、委任の範囲、個別の対応案）"]
    P1 --> P2{"完了条件ごとに確かめ方を定められるか"}
    P2 -- 定められない条件がある --> P3[/"依頼元に示し、言い直しを問う"/]
    P3 --> P1
    P2 -- すべて定められる --> D1[/"「対応方針」の節の全文を示し、承認を問う"/]
    D1 --> D2{"承認か"}
    D2 -- 修正あり --> D3["修正を反映"]
    D3 --> D1
    D2 -- 承認 --> C1["承認された対応方針からタスクに分け、plan.mdを書く（タスク、完了条件と確かめ方、変えてよい範囲、依存）。計画への承認は問わない"]
    C1 --> E1["タスクを依存の順に実行する（タスクの実行ループ）"]
    E1 --> F1[["評価者を起動（reviewer-<n>）"]]
    F1 --> F2{"判定"}
    F2 -- 差し戻し --> F3{"指摘が指すタスクがあるか"}
    F3 -- ある --> F4["そのタスクを差し戻す"]
    F4 --> E1
    F3 -- ない --> F5{"タスクの追加で対応方針が変わるか"}
    F5 -- 変わる --> F6["「対応方針」の節を改める"]
    F6 --> D1
    F5 -- 変わらない --> F7["タスクを追加し、「経過」の節に書く"]
    F7 --> E1
    F2 -- 承認 --> G1["指示書が求める後処理（コミット等）を行う"]
    G1 --> G2["plan.mdの「結果」の節を書き、依頼元に報告する"]
    G2 --> T([終了])
```

### タスクの実行ループ

全体の流れの「タスクを依存の順に実行する」で、タスクごとに次を繰り返す。互いに依存せず、変えてよい範囲が重ならないタスクは同時に進めてよい。

```mermaid
flowchart TD
    S([タスク開始]) --> W1[["実行者を起動（worker-<n>）"]]
    W1 --> W2{"返答の結論"}
    W2 -- 判断待ち --> W3["「判断を求める事項」の節を読む"]
    W3 --> W6{"事項ごとに、委任の範囲の内か"}
    W6 -- 内 --> W7["統括が裁定し、「裁定」の節に書く"]
    W6 -- 外 --> W8[/"依頼元に一件ずつ問い、答えを「裁定」の節に書く"/]
    W7 --> W1
    W8 --> W1
    W2 -- 中断 --> W4[/"報告の全文を読んで依頼元に示し、判断を問う"/]
    W4 --> U(["依頼元の判断に従う"])
    W2 -- 完了 --> R1[["評価者を起動（reviewer-<n>）"]]
    R1 --> R2{"返答の判定"}
    R2 -- 承認 --> R3["レビューを読まずにタスクを完了にする"]
    R3 --> T([次のタスクへ])
    R2 -- 差し戻し --> R4{"同じタスクの差し戻しが3回に達したか"}
    R4 -- 達した --> R5[/"レビューの指摘と経過を依頼元に示し、判断を問う"/]
    R5 --> U
    R4 -- 未満 --> W5["「指摘」の節を読んで対応を決め、レビューのパスを渡す"]
    W5 --> W1
```
