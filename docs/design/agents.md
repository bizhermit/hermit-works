# エージェント定義の設計

エージェント種別の設計と書式の定めを、この1ファイルに集約して置く。個々のエージェントの動作の正本は`plugin/agents/`配下のエージェント定義そのものである。

## エージェントの設計書は本ファイルに集約する

エージェント定義は宣言的な文書であり、それ自体が設計の記述を兼ねる。定義から読み取れない補足（判定条件の根拠・境界条件・選ばなかった案）は、エージェントごとのファイルを作らず本ファイルへ収める。エージェント間で境界の概念が似通い共通の記述になりやすく、個別の分量も小さいためである。特定エージェントに固有の補足が必要になったら、本ファイル内にそのエージェントの節を設ける。全エージェントへの網羅は求めない。

## 書式規約

エージェント定義の本文に適用する。frontmatterは対象外。狙いは、規範1件ごとの検索性と遵守の安定である。1行に複数の規範を詰めると個々の遵守率が下がり、末尾括弧に埋めた例外は無視と過剰適用の両方向にぶれやすく、強調がないと絶対規範と既定動作の区別がつかない、という仮説に基づく（挙動への効果は未計測。計測するならプローブ課題によるbefore/after比較を用いる）。

1. **1項目1規範**：1つの箇条書きに規範文は1つだけ置く。付随する条件・例外・委ね先は下位の箇条書きへ降ろす。
2. **ラベル先頭**：各項目を「**ラベル**：規範文」で始める。ラベルは短い名詞句とし、他所からの参照名を兼ねる（「前段」「上記」等の位置参照は使わず、ラベル名で参照する）。
3. **分岐は番号付きリスト**：優先順位・順序のある決定手順は`1. 2. 3.`の番号付きリストで書く。
4. **例外はマーカー付き下位項目**：例外・対象外は末尾括弧に埋めず、`例外:`または`対象外:`を頭に付けた下位項目にする。マーカーの語義を守り、除外でない補足義務にはマーカーを付けない。亀甲括弧〔〕を含む二重ネストの括弧で規範・条件を書かない（短い言い換え・具体例の括弧は可）。
5. **強調の意味固定**：boldの用途は(a)項目ラベル、(b)解除不能な禁止・義務の動詞（例: **従わない**・**実行しない**・**独断で決めない**）の2つに限る。通常規範の動詞には使わず、boldの信号価値を薄めない。
6. **長さ上限**：1項目の規範文は2文・目安120字まで。超えたら分割のサインとする。
7. **見出しとラベルの使い分け**：複数項目を束ねる命名グループ（分野に含む/分野に含まない・下限ガードレール等）は`###`見出し＋フラットな箇条書き、単一の規範は太字ラベル付き箇条書きとする。

太字ラベルへの統一（見出しを使わない案）は不採用とした。見出しはアウトライン表示に乗り、保守側の視認性で勝るためである（利用者裁定）。

## 共有節の保守

受任判断・作業原則・ガードレールの共通部・下限ガードレール・報告・リーダーの委任の各節は、全エージェント定義（該当する変種の範囲）で逐語同一を保つ。編集するときは1ファイルを直して個別に済ませず、正とする1箇所を直してから全ファイルへ機械的に展開し、一致をdiff等で検証する。手作業の並行編集は文言のドリフトを生む。
