# Hermit Works 設計書

## リポジトリ構成

```text
/                          # 保守側（非配布）
├── .claude-plugin/
│   └── marketplace.json   # マーケットプレイス定義
├── CLAUDE.md              # 本リポジトリ保守用の指示
├── LICENCE                # ライセンス全文の正本
├── docs/
│   └── design/            # 設計書（本ディレクトリ）
│       ├── agents/        # エージェント設計書
│       └── skills/        # スキル設計書
└── plugin/                # 配布側（インストール時にコピーされる範囲）
    ├── .claude-plugin/
    │   └── plugin.json    # プラグインマニフェスト
    ├── LICENCE            # 配布用の写し
    ├── agents/            # エージェント
    ├── skills/            # スキル
    └── assets/            # 共通資材
```

## スキルとエージェントの境界

同じエージェントが別のスキルを使用しても変わらない記述はエージェントに、同じスキルを別のエージェントが使用しても変わらない記述はスキルに、どちらを替えても変わらない記述はどちらにも書かず上位の規範とする。

### スキルに書くべきもの

- 入り口と出口（I/O）：このスキルを実施するために必要な情報（input）と、そこから導き出される結果（output）を書く
- 手順（Flow）：進む道（rail）と止まる条件（traffic light）。進む道は実施するエージェントに任せてよいが、止まる条件と、そこで残す記録は必ず書く

### エージェントに書くべきもの

- 概要：どのような立場の人物で、何を軸に何を担うかを書く
- 作業方針：担う物事ごとに、概要と境界を書く。境界は担わない側を示すものであり、そこに委ね先の名前は書かない。誰が担うかは手順が割り当てる。次の三つを満たす記述だけを置く
    - スキルを替えても変わらない。案件の手順や記録の書き方は入らない
    - エージェントを替えると変わる。憲章の言い換えは入らない
    - 他のエージェントやスキルの手順を指さない
- 憲章、参照データの扱い、報告前の自己点検：どちらを替えても変わらない上位の規範であり、エージェント固有の記述ではない。正本は[エージェント設計書](agents/index.md)のひな型にあり、各エージェントはそれを逐語で写す。プラグインのエージェントが`CLAUDE.md`のロードに頼らず規範を持つためである
