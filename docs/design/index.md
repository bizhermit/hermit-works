# Hermit Works 設計書

## リポジトリ構成

```text
/                          # 保守側（非配布）
├── .claude-plugin/
│   └── marketplace.json   # マーケットプレイス定義
├── CLAUDE.md              # 本リポジトリ保守用の指示
├── LICENCE                # ライセンス全文の正本
├── docs/
│   └── design/            # 設計書（本ディレクトリ）
│       ├── agents/        # エージェント設計書
│       └── skills/        # スキル設計書
└── plugin/                # 配布側（インストール時にコピーされる範囲）
    ├── .claude-plugin/
    │   └── plugin.json    # プラグインマニフェスト
    ├── LICENCE            # 配布用の写し
    ├── agents/            # エージェント
    ├── skills/            # スキル
    └── assets/            # 共通資材
```

## スキルとエージェントの境界

同じエージェントが別のスキルを使用しても変わらない記述はエージェントに、同じスキルを別のエージェントが使用しても変わらない記述はスキルに、どちらを替えても変わらない記述はどちらにも書かず上位の規範とする。

### スキルに書くべきもの

- 入り口と出口（I/O）：このスキルを実施するために必要な情報（input）と、そこから導き出される結果（output）を書く
- 手順（Flow）：進む道（rail）と止まる条件（traffic light）。進む道は実施するエージェントに任せてよいが、止まる条件と、そこで残す記録は必ず書く

```
---
name: <名前>
description: <説明>
argument-hint: <引数の形>
---
```

### エージェントに書くべきもの

- 担当分野（Responsibility/inability）：一つの物事ごとに、担う側（対象）と担わない側（対象外）の線を引いて書く。対象外に委ね先の名前は書かない。誰が担うかは手順が割り当てる
- 作業方針：担当分野の内側での流儀を書く。次の三つを満たす記述だけを置く
    - スキルを替えても変わらない。案件の手順や記録の書き方は入らない
    - エージェントを替えると変わる。憲章の言い換えは入らない
    - 他のエージェントやスキルの手順を指さない

```
---
name: <名前>
description: <説明>
---

# hw:<名前>

<所属グループと役職>

## 担当分野

- **<物事>**
    - 対象：<担うのはここまで>
    - 対象外：<ここからは担わない>

## 作業方針

- **<流儀の名前>**：<内容>
```
