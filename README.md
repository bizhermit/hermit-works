# Hermit Works

Claude Code用のプラグイン。要望を言語化して指示書にする。指示書を受けて、計画、実行、レビューをそれぞれ別の人物が行い、成果物を仕上げる。

## インストール

マーケットプレイスを登録し、プラグインをインストールする。`<scope>`は`user`、`project`、`local`のいずれかで、省くと`user`になる。

```bash
claude plugin marketplace add bizhermit/hermit-works --scope <scope>
claude plugin install hw@hermit-works --scope <scope>
```

| `<scope>` | 書き込む設定ファイル | 有効になる範囲 |
| :- | :- | :- |
| `user` | `~/.claude/settings.json` | 自分のすべてのプロジェクト |
| `project` | `<プロジェクト>/.claude/settings.json` | そのプロジェクトの貢献者全員 |
| `local` | `<プロジェクト>/.claude/settings.local.json` | そのプロジェクトの自分だけ |

`project`の設定を共有された貢献者は、同じ二つのコマンドを`--scope project`で一度実行する。

指示書と案件記録はプロジェクト直下の`.hw/`に置かれるため、`.gitignore`に次を書き足す。

```gitignore
.hw/
```

## 使い方

### `/hw:request`：要望を指示書にする

```text
/hw:request <要望または相談>
```

相談の形で始めてもよい。依頼元に問うのは、目的が定まらないときと、指示書全体に対する問題（現物を指す語が見つからない、答えが互いに矛盾する等）があるときである。目的が定まるまで、依頼元の意見を言語化して確かめ、要るなら目的の候補を示す。どう対処するか（どのファイルにどういう修正を行うか、対象範囲、完了条件等）は、依頼元から言われない限り問わず、`/hw:execute`が対応方針で定める。依頼元の承認を得てから、指示書を`.hw/instructions/`に出力する。

### `/hw:execute`：指示書を実行する

```text
/hw:execute <指示書のパス>
/hw:execute <案件ディレクトリのパス>
```

指示書から対応方針を立てて、依頼元に承認を問う。承認を得たら実行計画を立て、タスクごとに実行者と評価者を起動し、評価者が承認するまで実行者に差し戻す。すべてのタスクが完了したら全体レビューを行い、結果を依頼元に示して成果物を認めるか差し戻すかを問う。認めたら案件を完了にする。引数に案件ディレクトリのパスを与えると、止まった案件を記録から再開する。引数を省くと、`.hw/instructions/`にある指示書の一覧と、止まっている案件の一覧を示し、どれを実行するか、またはどれを再開するかを問う。

### `/hw:skillify`：案件記録から繰り返し現れるパターンを割り出し、スキルにするための指示書を作る

```text
/hw:skillify
```

`.hw/cases/`の完了した案件を種類に仕分け、複数の案件に繰り返し現れるパターン（同じ種類の案件の手順、同じタスク、同じ種類の組み合わせ）を割り出す。候補をスキルの構成（利用者が呼ぶ入口と、他のスキルから呼ばれる部品）として頻度とともに示し、依頼元が選んだ候補ごとに、プロジェクトの`.claude/skills/<name>/SKILL.md`としてスキルを作る（または既存のスキルを変える）ための指示書を1通作る。指示書は`/hw:execute`で実行する。繰り返しが無ければ、スキルにするのを見送ると報告する。作られるスキルはこのプラグインに依存しない。

### `/hw:visualize`：案件の資源と進め方をHTMLで可視化する

```text
/hw:visualize <案件ディレクトリのパス>
/hw:visualize .hw/cases/
```

`/hw:execute`の案件記録を可視化する。引数には、案件ディレクトリのパス、または案件の親ディレクトリのパスを与える。親ディレクトリなら、その直下の全案件を可視化する。使い方の2行目は、親ディレクトリとして`.hw/cases/`を与える例である。引数を省くと、`.hw/cases/`にある案件の一覧を示し、どれを可視化するかを問う。案件ファイル（`plan.md`、タスクごとの報告とレビュー、全体レビュー）の読み取りはスキルの実施者が行い、分析項目ごとの値を`<案件>.json`に書く。出力先は`.hw/analysis/`であり、案件ごとの`<案件>.json`と`<案件>.html`、案件一覧の`index.html`を書く。`<案件>.json`には、案件ファイルから取り出した値と、セッション記録の集計（トークン量、所要時間、費用）が載る。`<案件>.html`には、概要（目的）、基本情報（状態、着手日時、完了日時、所要時間（全体、AI、待機をそれぞれ一行）、セッションID、作業ブランチの表）、費用（合計のトークン量と合計の費用を示す大きなカード、担当ごとの費用とトークン量を示す小さなカード、トークン量と費用の、担当ごと、モデルごと、タスクごとの棒グラフ）、処理（全体、AI、待機の所要時間と担当の起動回数を示すカード、着手からの段階、タスクごとの担当の起動、全体レビュー、利用者レビュー、裁定、待機の区間を時系列に並べた図、段階とタスクの流れをタスクの依存と差し戻しの矢印とともに示すフローチャート）、タスク一覧（初期状態は閉じている。タスクごとの概要と、横に並べた二種類の表。一つは状態、開始日時、完了日時、所要時間（トータル）、所要時間（AI）、所要時間（待機時間）、差戻回数、依存のタスクの表、もう一つは担当の起動ごとの役割、agent（エージェントの種類）、model、effortの表。担当の表は差し戻しごとの組に分けて組を縦に並べ、組の中の表を横に並べる。初回の組には見出しが無く、2組目からは「差戻1」「差戻2」…の見出しが付く。画面の幅が足りなければ、二種類の表と組の中の表は折り返して縦に並ぶ。表の下に成果物と変えてよい範囲が載る）、レビューと差し戻し（差し戻しの回数と理由、裁定、評価者の提案、変更量等。初期状態は閉じている）の節が載り、取れなかった指標は「不明」とその理由が載る。`index.html`には、案件の一覧の表（先頭の列は1から並ぶ番号）が載り、案件ごとの指標を並べて案件を比べられる。トークン量、所要時間、担当の起動ごとのagent、model、effortは、Claude Codeのセッション記録（`~/.claude/projects/`。環境変数`CLAUDE_CONFIG_DIR`で設定ディレクトリを変えていれば、その下の`projects/`）から取る。費用は、プラグインに同梱する単価表（`pricing.json`）から求める。単価表はモデルごとの単価と、単価を写した日付と出所を持ち、書き換えてよい。単価表は標準の単価だけを持ち、標準以外の呼び出し（`service_tier`または`speed`が`standard`以外のもの）の数（無ければ0件）が`<案件>.html`に載る。セッション記録の集計とHTMLの描画はPython 3のスクリプトが行うため、Python 3が要る。
