# 段階4 実行計画

対応方針を、担当に委ねられる計画に直列に分解する。

## 産物

- 計画一覧`<案件ディレクトリ>/plans/index.md`
- 各計画の`<案件ディレクトリ>/plans/<番号>_<計画名>/index.md`
- 終点が計画なら、工数見積`<案件ディレクトリ>/estimate.md`。案件の`index.md`からリンクする

## 手順

1. 対応方針を計画に分解する。計画は次を満たす単位とする。
    - 一つの成果物を担い、単独で検収できる。完了条件が検証できる形で書ける。
    - 一人の担当が一つのセッションで終えられる大きさである。
    - 対象とするファイルと範囲が明らかである。
2. 計画を依存関係の順に並べ、番号を付ける。依存なく並列に進められる計画には同じ実行順を与える。同じ実行順の計画は対象が重ならないようにする。
3. 計画一覧を作る。
4. 計画ごとにディレクトリと`index.md`を作る。担当が計画の`index.md`と案件の`index.md`だけで着手できるように、根本の目的までの連なり、完了条件、対象と境界、検収の観点、担当の種別と根拠を書く。
5. 終点が計画なら、ひな型から工数見積を作る。単位は依頼原文か既決に定めがあればそれに従い、無ければ人時とする。計画ごとに工数と根拠を書き、合計と前提を書く。工数は推論であり、確度を添える。
6. 品質ゲートを通す。
7. 自走レベルの定めに従って確認を受ける。

## 評価基準

- すべての計画が完了すれば対応方針が実現され、漏れも重複もない。
- 各計画の完了条件が検証できる形で書かれている。
- 依存関係と実行順が整合し、同じ実行順の計画の対象が重なっていない。
- 各計画が一人の担当が一つのセッションで終えられる大きさである。
- 各計画の`index.md`が、担当が着手するのに足りる情報を持ち、根本の目的までの連なりが切れていない。
- 対応方針に無い作業が計画に加えられていない。
- 終点が計画なら、工数見積が計画ごとに根拠を持ち、合計が計画の工数と一致し、前提が明示されている。
