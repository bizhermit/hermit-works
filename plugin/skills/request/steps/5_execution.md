# 段階5 分担実行

計画を実行者に委ね、完了した計画を計画ごとに検収して案件に受け入れる。

## 産物

- 各計画の成果物
- 各計画の`index.md`のタスク、検収、裁定記録
- 計画一覧の状態と検収

## 手順

実行順ごとに次を繰り返す。前の実行順の計画がすべて検収に合格してから、次の実行順に進む。

1. 同じ実行順の計画を、一つの応答で並列に実行者へ委ね、計画一覧の状態を進行中にする。委任の依頼文は`SKILL.md`の委任の定めに従い、計画の`index.md`のパスを渡す。実行者の担う内容は次である。
    - 計画の`index.md`と案件の`index.md`を読んでから着手する。
    - タスクを進め、タスクの状態を計画の`index.md`に書きながら進める。
    - 完了条件を現物で確かめ、確かめ方と結果を報告する。
    - 裁定が必要な事柄は実行せず、判断材料を計画の`index.md`の裁定待ちに書いて止まり、報告する。
2. 実行者が裁定待ちで止まったら、統括が裁定を取り次ぎ、裁定記録に追記して、同じ実行者に続きを委ねる。
3. 実行者が完了を報告したら、検収を行う。
4. 検収に合格したら、計画一覧の状態を完了にし、検収欄に判定と差し戻し回数を書く。検収の指摘と対処は計画の`index.md`の検収に書く。差し戻しなら、指摘を実行者に渡して直させ、同じ評価者に再検収を求める。差し戻しの上限は品質ゲートと同じである。
5. 計画の裁定記録と残論点・保留に、案件の目的や他の計画に関わる事項があれば、案件の`index.md`に転記する。

すべての計画が検収に合格したら段階6へ進む。

## 検収の基準

検収は品質ゲートである。評価者は実行者とは別の人物であれ。

- 完了条件が現物で確かめられている。テストがあるなら評価者自身が実行して結果を見る。
- 対象と境界の外に変更が無い。
- 成果物が`CLAUDE.md`の出力の表記に従っている。
- 計画の`index.md`のタスクの状態と記録が現状と一致している。
- 実行者が推論のまま残した事項が、事実として報告されていない。
- 裁定を経ずに実行者が決めた設計や要件が無い。
