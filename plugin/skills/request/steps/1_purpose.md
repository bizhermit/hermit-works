# 段階1 背景と目的の裁定

依頼を、根本の目的まで遡った背景と目的に組み直し、利用者の裁定を受ける。以降のすべての段階はここで決まった目的に仕える。

## 産物

案件の`index.md`の次の項目。

- 背景：何が起きていて、なぜ今この依頼があるのか
- 目的：何が果たされれば案件が完了か。検証できる形で書く
- スコープ外：この案件でやらないこと
- 制約：依頼に付された制約と、`CLAUDE.md`など定められた規則から来る制約

## 手順

1. 依頼原文を読み、`CLAUDE.md`を引いて、既決の事項を確かめる。
2. 背景、目的、スコープ外、制約を書く。依頼原文から読み取れることと、統括が補ったことを分けよ。補ったことは仮定と明示する。
3. 依頼原文から読み取れず、仮定では進められない事項があれば、1件ずつ利用者に問う。この問いは本手順が定めた問いであり、裁定ではない。得た答えは依頼原文の末尾に追記する。
4. 品質ゲートを通す。
5. 背景、目的、スコープ外、制約と、統括が補った仮定を判断材料として利用者に示し、この目的で進めてよいかの裁定を問う。修正があれば反映し、手順4からやり直す。承認を裁定記録に追記する。

## 評価基準

- 目的が依頼原文と矛盾せず、依頼に無い目的が加えられていない。
- 目的が根本の目的まで遡れており、依頼に書かれた手段の字義に留まっていない。
- 目的が、完了したかを検証できる形で書かれている。
- 統括が補った箇所が仮定として明示されている。
- スコープ外と制約が目的と整合している。
- 既決の事項を問い直していない。
