# 段階2 現状調査

対応方針を選ぶのに必要な事実を、検証済みの形で揃える。

## 産物

- 案件の`index.md`の現状調査の項目。決まったこと、すなわち検証済みの事実と、残った不明を書く
- `index.md`に収まらない調査結果は`<案件ディレクトリ>/survey/`に置き、`index.md`からリンクする

## 手順

1. 目的から、何が分かれば対応方針を選べるかを調査項目として列挙する。項目ごとに、何を現物に当たって確かめるかを書く。
2. 項目ごとに調査員へ委ねる。互いに依存しない項目は並列に進める。調査員には項目ごとに、検証済みの事実とその現物、推論、不明を分けて報告させる。
3. 調査員の報告から、検証済みの事実と不明を`index.md`にまとめる。推論は事実として書かず、不明は推論で埋めない。
4. 品質ゲートを通す。
5. 調査で分かったことの要点を利用者に伝える。裁定は問わない。

## 評価基準

- 各事実に現物（パス、実行したコマンド、結果）が添えられ、現物がその事実を裏付けている。
- 検証済み、推論、不明が区別され、推論や不明が事実として書かれていない。
- 対応方針を選ぶのに必要な項目が漏れていない。
- 調査が目的に遡れない範囲へ広がっていない。
