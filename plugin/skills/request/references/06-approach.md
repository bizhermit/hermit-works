# 手順6 対応方針の裁定

## 論点の分解と裁定

- `current-condition-report.md`を踏まえ、対応方針の論点を裁定できる単位まで分解する。
- 後戻りコストの大きい論点から順に問う。目安3〜7問で打ち切り、残りは推奨を添えて実行計画へ回す。事実確認・慣習的な軽い確認は一括提示してよい。

## 新規導入の裁定

- 方針に新規導入（依存・ツール・仕組みの追加）が含まれる場合、導入の可否（Whether）を独立の裁定として最初に提示し、進め方（How）の裁定より先に確定させる。見送りと裁定されたものは以降の方針・計画から除く。
- 評価観点: 必要性（導入せずに済む方法があるか）・代替手段・コスト（導入と維持）・撤退経路。
- 採否とその根拠は`approach.md`に記録する。対象リポジトリの正式文書へ記載すべき性質の採否は、利用者に正式文書への記載を促す。

## 分割の判断

- 対応方針で作業規模が計画に収まらない場合は、子案件への分割を検討し、分割案を裁定として提示する。
- 分割は2類型。**完全並列型**=兄弟と独立に進められるもの。目安3問——(1)兄弟の結果を参照せずゴールが書けるか (2)兄弟の完了を待たず検収できるか (3)その子だけ完了して止まっても対象が壊れないか。**直列型**=作業規模が案件相当に達し、段階を踏む方が品質が上がるもの。直列を維持する。
- 使い分けの目安: 案件の前半（背景ゴール・調査・方針）を共有できるなら計画分割、工程ごとに独自の調査・方針裁定が要るなら子案件。目安は機械的に固定せず、評価者の意見と利用者の利用状況を材料に、ケースバイケースで利用者が裁定する。
- 分割裁定が確定したら、親の`index.md`の「子案件」節へ先登録する（SKILL.mdの「子案件」節に従う）。

## 成果物

- `approach.md`（案件ディレクトリ直下）を作成する。必須項目:
  - 採用した方針と、その方針で到達するゴール。
  - 検討した代替案と、案間の利害得失。
  - 新規導入の採否と根拠（該当時）。
- 裁定の記録の置き場はSKILL.mdの「記録と状態」節に従う。
