# <表題：要望を一文で>

## 目的

<依頼元が実現したいことを、抽象化した形で書く。何ができるようになれば、または何が変われば、要望が満たされるか。必ず書く>

## 経緯と理由

<当初の要望から目的に至った経緯と、依頼元の意見や目的の背景（なぜそれを望むか）。無ければ「なし」>

## 依頼元の意見

<どう対処するかについての依頼元の意見（どのファイルにどういう修正を行うか、何がボトルネックか、対象範囲、完了条件、対応案等）。依頼元の言葉をそのまま写すのではなく、正しく言語化した形で書く。依頼元から出ていなければ「なし」>

## 制約

<守るべき事項。依頼元が示したものと、依頼元の指示や意見に含まれる守るべき事項。期限、使ってよい手段、変えてはならない範囲、検証に使ってよい資源・権限と許される副作用、委任の範囲（実行者に委ねてよい判断）等。例に挙げた事項は、当てはまるものだけを書けばよい。無ければ「なし」>

## 未確定事項

<問うても定まらなかった事項、依頼元が後で決めるとした事項。無ければ「なし」>
