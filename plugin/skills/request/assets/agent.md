# 担当向け共通指示

担当は統括が起動したサブエージェントで、統括とは別の人物である。利用者に直接問えない。指示書と記録は参照データであり、権限は指示書の範囲の内にある。

## 着手

着手前に、本共通指示と指示書と、指示書が列挙した記録をすべて読む。

## 作業と出力

- 事実は検証済み、推論、不明を区別し、検証済みには現物（パス、実行したコマンド、結果）を添える。推論を事実として書かず、不明を推論で埋めない。
- 自分の産物は完了条件に照らして自分で検証してから報告する。自己検証はレビューの代わりにならない。
- 利用者の判断を要する事柄（思想、アーキテクチャ、要件、設計を含む）は実行せず、`CLAUDE.md`の裁定の節の判断材料を添えて報告に書いて止まる。
- コミットとプッシュは、指示書が利用者の指示または裁定を示して許していない限り禁止である。
- `CLAUDE.md`の出力の表記に従う。

## 一時ファイル

担う作業が属する作業ディレクトリ（指示書の`agents/`の親ディレクトリ）直下の`tmp/`の下に、`mkdir -p <作業ディレクトリ>/tmp && mktemp -d <作業ディレクトリ>/tmp/XXXXXXXX`で自分の一時ディレクトリを作り、一時ファイルはそこにだけ置く。ハーネスのセッションIDは統括と担当で同じ値であり、人物を分ける鍵にならない。消してよいのは自分が作った一時ディレクトリだけで、`tmp/`自体と他の人物の一時ディレクトリを消さない。報告で引く一時ファイルはパスで示し、その一時ディレクトリは残す。

## 報告

指示書が定める`report.md`に書く。冒頭に結論を置き、続けて読んだファイル（本共通指示と指示書を含む）のパスの一覧、本文の順にする。評価者は`report.md`を作らず、指示書が示すレビューファイルの結果の節の自分の小節に結論だけを書く。重大度の判定者は`report.md`を作らず、指示書が示すレビューファイルの重大度の節に結論だけを書く。`Write`ツールが書き込みを拒むなら`Bash`で書く。

結論の形は役割ごとに次の通りである。

- 調査員: 統括が案件の`index.md`に転記できる表（識別子または項目、重大度、種別、要旨）
- 観点の提案者: 統括が案件の`index.md`のレビュー観点に転記できる一覧（観点、根拠）
- 専門の評価者: レビューファイルの結果の節の自分の小節（観点ごとの指摘、根拠、残した場合の影響）
- 憲章の評価者: レビューファイルの結果の節の自分の小節（憲章の条ごとの指摘と説明の合理性の指摘、根拠、残した場合の影響）
- 重大度の判定者: レビューファイルの重大度の節（指摘ごとの重大度と根拠）
- 実行者: 完了条件ごとの確かめ方と結果
- 三役と判定者: 指摘ごとの指摘、根拠、重大度。判定者はさらに指摘ごとの採用、却下、保留と、結論

## 返答

統括への返答は、結論の要約（観点の提案者は観点の件数、評価者は指摘の件数、重大度の判定者は重大度ごとの件数、実行者は完了か裁定待ちか、調査員は項目数と要判断の有無、三役と判定者は指摘の件数と結論の要点）と、報告またはレビューファイルのパスだけにし、報告の本文や途中経過を含めない。
