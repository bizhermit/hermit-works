# hw:request

依頼元の要望を、引数と対話を通して言語化し、指示書として残す。

言語化とは、依頼元が既に持っている要望を書き出すことであり、実施者が内容を定めることではない。指示書の各節は依頼元の言葉で書き、実施者の解釈・提案・調査結果を加えない。依頼元から引き出せなかった事項は、補わずに未確定事項として残す。

## 入力

- 引数：$ARGUMENTS
- 運用：定められた規則（`CLAUDE.md`、運用手順書等）のうち、外部トラッカーの使用を定めた記述

引数には、要望と、出力先の指定（任意）を併記してよい。

## 指示書

雛形は[templates/instruction.md](${CLAUDE_SKILL_DIR}/templates/instruction.md)である。第1見出しが表題、それ以降が本文である。

- 依頼原文には、引数と、対話における問いと答えを、受けた順にそのまま記す。要約しない。
- 目的、背景、対象と範囲、完了条件、制約の各節は、依頼原文にある語で記す。依頼原文に該当が無く、依頼元が該当なしと答えた節は「なし」と記す。
- 未確定事項には、問うても定まらなかった事項と、依頼元が後で決めるとした事項を記す。

## 手順

1. 引数を読む。引数が無ければ、要望を問う。
2. 引数と答えに、現物を指す語（ファイル、画面、機能、課題番号等）があれば、リポジトリ、または依頼元が示す所在で実在と一意性を確かめる。見つからない、または複数に該当する場合は、判断を求める問いとして依頼元に問う。所在が示されず確かめられないものは、未確定事項に残す。指示対象の特定を超える調査は行わない。
3. 雛形の節ごとに、依頼原文で満たされるかを確かめる。満たされない節は、意向を聞く問いとして一件ずつ問う。
4. 出力先を、出力先の節に従って決める。種別は定まるが所在（リポジトリ、プロジェクト、パス等）が定まらない場合は、判断を求める問いとして問う。
5. 指示書の草案と出力先を依頼元に示し、この内容で作成してよいかを問う。修正があれば反映して再び示す。承認を得るまで出力しない。
6. 出力先へ出力し、作成した課題のURLまたはファイルのパスを報告する。

## 問い方

問いは、意向を聞く問いと、判断を求める問いの二種類である。いずれも、問いが複数あっても並べて示さず一件ずつ問い、答えを依頼原文に追記してから次へ進む。問いの本文と判断材料の形式は、依頼元の指定があればそれに従う。

### 意向を聞く問い

指示書の節を満たすための問いである。判断を求めるものではなく、案を示す前に依頼元の考えを聞くものである。三段の対話は用いず、目的と、現物で確かめた要点を示したうえで、どのように変えたいか、その構想や意向を聞く。

- 依頼原文で既に定まる事項は問わない。現物で確かめられる事項は問わず、確かめる。
- 問いは節の名称ではなく、依頼元が答えられる形にする。例：完了条件であれば「何が達成されたら完了とするか」。

### 判断を求める問い

判断を求めるのは、実施者が判じきれない事項（指示対象が一意に定まらない、依頼原文が互いに矛盾する等）と、実施者の権限の外にある判断（出力先の所在、範囲の取捨等、依頼元にしか決められない事項）である。三段の対話で進める。課題を示し、方針を確かめ、案を示す順である。

1. 課題を示す：(a)問題とその影響範囲、(b)原因のみを示し、依頼元の意見や構想を聞く。実施者の案はこの段では示さない。
2. 方針を確かめる：意向を汲んで方針を言語化し、依頼元の構想を言語化したものであるかを確かめる。合っていると答えるまで次の段へ進まない。確かめるのは進めるか否かの決定ではなく、言語化の当否である。
3. 案を示す：確かめた方針の内で、(c)複数の案と各案のゴール、(d)利害得失、(e)推奨とその根拠を示し、判断を受ける。第2段で確かめた方針が手段まで定めている場合はこの段を省き、確かめた答えを判断とする。省いた理由を依頼原文に記す。

推奨は既定値ではない。依頼元が推奨と逆の案を選んだ場合、矛盾があれば一度だけ指摘し、それでも維持されたら従う。

## 出力先

次の順で決める。上位で定まれば下位は参照しない。

1. 指定：引数または対話で依頼元が示した出力先
2. 運用：定められた規則が外部トラッカーの使用を定めていれば、そのトラッカー
3. 既定：`${CLAUDE_PROJECT_DIR}/.hw/instructions/<YYYYMMDD>_<slug>.md`

いずれの出力先でも内容は同一の指示書であり、表題を課題の題名に、本文を課題の本文に充てる。

外部トラッカーへの課題の作成手順（接続手段、認証、種別やラベル等）は運用が定めるものであり、本スキルは定めない。運用の記述に従い、記述に無い事項は依頼元に問う。

既定のファイルは次のとおり作成する。

- `<YYYYMMDD>`は作成日（`date +%Y%m%d`）
- `<slug>`は表題を表す、ASCIIの小文字とハイフンからなる短い語（例：`login-password-toggle`）。同名のファイルが既にある場合は末尾に`-2`、`-3`と連番を付す
- ディレクトリが無ければ作成し、指示書の全文（表題を含む）をそのまま書き込む

## 停止条件

- 依頼元の答えまたは承認が得られない：問いを示したまま停止する。推測で補って進めない。
- 課題の作成に失敗した：失敗の内容（コマンドと応答）と、指示書の本文をそのまま示して停止する。別の出力先へ独断で出力しない。
