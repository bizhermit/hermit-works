# hw:request

依頼元の要望を、引数（要望または相談）と対話を通して言語化し、指示書として残す。本スキルを実施する人物は依頼元を支える立場であり、対話の中で依頼元の意見を言語化し、要るなら対応案を示してよいが、指示書に書くのは依頼元が確かめた内容だけである。引き出せなかった事項は、補わずに未確定事項として残す。

どう対処するか（どのファイルにどういう修正を行うか、何がボトルネックか、対象範囲、完了条件。以下「四点」）は対応方針であり、`hw:execute`が定める。本スキルは、四点を依頼元から言われない限り問わない。依頼元から出た四点についての意見は、「依頼元の意見」の節に、依頼元の言葉をそのまま写すのではなく、正しく言語化した形で書く。目的（抽象化された目的）は必ず定め、無ければ問う。

## 入力

- 引数：$ARGUMENTS
- 運用：定められた規則（`CLAUDE.md`、運用手順書等）のうち、外部トラッカーの使用を定めた記述

引数は、要望または相談である。相談とは、実現したいことが要望の形で示されず、どうすればいいかを問う形の引数である。

## 指示書

雛形は[templates/instruction.md](${CLAUDE_SKILL_DIR}/templates/instruction.md)である。第1見出しが表題、それ以降が本文である。

- 「目的」の節には、依頼元が実現したいことを、抽象化した形で書く。目的は必ず定める。定まらないときは、「問い方」の節の手順に従い、依頼元の意見を言語化して確かめ、要るなら目的の候補を示し、定まるまで対話する。相談は、問いに対する依頼元の意見と同じに扱う。
- 「経緯と理由」の節には、当初の要望から目的に至った経緯と、依頼元の意見や目的の背景（なぜそれを望むか）を書く。経緯と理由は問わず、対話で出たものを書く。無ければ「なし」と書く。
- 「依頼元の意見」の節には、どう対処するかについての依頼元の意見（四点、対応案等）を、依頼元の言葉をそのまま写すのではなく、正しく言語化した形で書く。依頼元から出ていなければ「なし」と書く。
- 「制約」の節には、守るべき事項として、依頼元が示したものと、依頼元の指示や意見に含まれるものを書く。無ければ「なし」と書く。
- 「未確定事項」の節には、問うても定まらなかった事項と、依頼元が後で決めるとした事項を書く。無ければ「なし」と書く。

## 手順

1. 引数を読む。引数が無ければ、要望を問う。
2. 引数と答えに、現物を指す語（ファイル、画面、機能、課題番号等）があれば、リポジトリ、または依頼元が示す場所に実際にあり、一つに定まるかを確かめる。場所が示されず確かめられないものは、「未確定事項」の節に残す。その語がどの現物を指すかを確かめる以上の調査は行わない。
3. 出力先を、「出力先」の節に従って決める。
4. 引数と答えから指示書の草案全体を、依頼元に示さずに作り、指示書全体に対する問題を見つけて依頼元に問う。問いに示すのは問題だけであり、草案は示さない。草案を示すのは手順5である。一度に問う問題は、依頼元が答えられる量に絞る。問題とは、目的が定まらない、現物を指す語が見つからないまたは一つに定まらない、答えが互いに矛盾する、出力先の種別は定まるが場所（リポジトリ、プロジェクト、パス等）が定まらない、のいずれかに限る。四点は、無くても問題とせず、問わない。依頼元の答えは複数の節に及び、節は単独では定まらないため、節を一つずつ切り出して問わない。答えを受けたら、答えが影響するすべての節に反映して草案全体を改め、改めた草案全体について手順2から本手順までを再び行う。問題が無くなるまで繰り返す。
5. 指示書の草案全体と出力先を依頼元に示し、この内容で作成してよいかを問う。承認は指示書全体に対して得る。依頼元は草案全体を見て、「依頼元の意見」の節が依頼元の意見を正しく言い表しているかを確かめる。修正があれば、手順4と同じく影響するすべての節に反映して草案全体を改め、全体を確かめてから再び全体を示す。承認を得るまで出力しない。
6. 出力先へ出力し、作成した課題のURLまたはファイルのパスを報告する。

## 出力先

次の順で決める。上位で定まれば下位は参照しない。

1. 運用：定められた規則が外部トラッカーの使用を定めていれば、そのトラッカー
2. 既定：`${CLAUDE_PROJECT_DIR}/.hw/instructions/<YYYYMMDD>_<slug>.md`

いずれの出力先でも内容は同一の指示書であり、表題を課題の題名に、本文を課題の本文に充てる。

外部トラッカーへの課題の作成手順（接続手段、認証、種別やラベル等）は運用が定めるものであり、本スキルは定めない。運用の記述に従い、記述に無い事項は依頼元に問う。

既定のファイルは次のとおり作成する。

- `<YYYYMMDD>`は作成日（`date +%Y%m%d`）
- `<slug>`は表題を表す、ASCIIの小文字とハイフンからなる短い語（例：`login-password-toggle`）。同名のファイルが既にある場合は末尾に`-2`、`-3`と連番を付ける
- ディレクトリが無ければ作成し、指示書の全文（表題を含む）をそのまま書き込む

## 停止条件

- 依頼元の答えまたは承認が得られない：問いを示したまま停止する。推測で補って進めない。
- 課題の作成に失敗した：失敗の内容（コマンドと応答）と、指示書の本文をそのまま示して停止する。別の出力先へ独断で出力しない。
