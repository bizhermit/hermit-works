## 記録の置き先 <!-- memory -->

記録を書く前に、その記録が誰に属するかを決めよ。判断の根拠は内容であって、書きやすさではない。

- **個人の記憶に寄せるな**：利用者個人の好み・やり方に属するものだけを個人の記憶（memory）に置け。案件の決定・設計・経緯など、担当者が代わっても残すべきものは対象外である。
- **案件の記録は案件に置け**：進行中の作業の経緯・判断・成果物は、その案件・計画のディレクトリ（`.hw/cases/`・`.hw/plans/`配下）に置け。案件の`index.md`と計画の`index.md`が、その案件・計画の状態と判断の正本である。受けた裁定は、その案件・計画の`index.md`の「裁定記録」へ置け。ただし進行記録は正式な記録の場ではない。git管理外の作業記録であり、そこへの記載は恒久の文書・利用者資材への記録の代わりにならない。
- **`.hw/`はこの地図に限る**：`.hw/`に置けるのは次のものだけである。ここに無いディレクトリ・ファイルを`.hw/`へ新設するな。
  - `.hw/cases/`：案件の進行記録。案件ごとのディレクトリに`index.md`と作業ファイルを置く。
  - `.hw/plans/`：計画の進行記録。計画ごとのディレクトリに`index.md`と作業ファイルを置く。
  - `.hw/procedures/`：蒸留中の手順資産と、その索引`index.md`。手順のステップが参照するスクリプトは`.hw/procedures/scripts/`に置く。
  - `.hw/settings.json`：`hw:init`の展開記録。
- **案件を跨ぐ決定は恒久の文書へ収めよ**：案件を跨いで効かせると利用者が明示した決定は、利用者が指示する恒久の文書（`CLAUDE.md`・設計書など）へ収めよ。仮置きの場は設けず、収める先がなければその決定は案件の内側で終わる。明示がないものも案件の内側に留め、次の案件で必要になれば改めて諮れ。同じ決定を二箇所に残すな。
- **置き先がなければ止まれ**：上のいずれにも属さない記録は、置き先を自分で決めるな。個人の記憶に退避させたり作業用の一時領域に残したりせず、内容を利用者に示して置き先の判断を仰げ。
- **置き先未決を放置するな**：正式な置き場が未決の記録は、案件・計画の`index.md`に残課題として明示せよ。案件・計画を完了へ移す前に、残っている置き先未決を利用者に再提示し、記録する・しないの判断を得よ。記録しないと決めた場合は、その判断を裁定記録に残して閉じよ。
- **一時領域は捨てる前提**：作業用の一時領域（scratchpad等）は、その場で使い切るものだけを置け。残すべきものを一時領域に置いたままにするな。
- **リポジトリへ書くのは依頼に基づけ**：リポジトリ内のファイル（設計書等）は成果物である。自分の判断で記録を書き足すな。対象は成果物であり、本節が置き先を定めた運用記録（案件・計画の記録）は含まない。
