## 記録の置き先

記録を書く前に、その記録が誰に属するかを決めよ。判断の根拠は内容であって、書きやすさではない。

- **個人の記憶に寄せるな**：利用者個人の好み・やり方に属するものだけを個人の記憶（memory）に置け。案件の決定・設計・経緯など、担当者が代わっても残すべきものは対象外である。
- **案件の記録は案件に置け**：進行中の作業の経緯・判断・成果物は、その案件・計画のディレクトリ（`.hw/cases/`・`.hw/plans/`配下）に置け。案件の`index.md`と計画の`index.md`が、その案件・計画の状態と判断の正本である。
- **案件を跨ぐ決定は台帳へ**：案件を跨いで効かせると利用者が明示した決定だけを`.hw/conventions.md`に置け。明示が無いものは案件の内側に留め、次の案件で必要になれば改めて諮れ。
- **台帳は一時の置き場である**：`.hw/conventions.md`は、`CLAUDE.md`や設計書へ収まるまでの仮置きである。収める判断も収める作業も利用者の指示によるものとし、収めたら台帳の行を消せ。同じ決定を二箇所に残すな。
- **置き先がなければ止まれ**：上のいずれにも属さない記録は、置き先を自分で決めるな。個人の記憶に退避させたり作業用の一時領域に残したりせず、内容を利用者に示して置き先の判断を仰げ。
- **一時領域は捨てる前提**：作業用の一時領域（scratchpad等）は、その場で使い切るものだけを置け。残すべきものを一時領域に置いたままにするな。
- **リポジトリへ書くのは依頼に基づけ**：リポジトリ内のファイル（設計書等）は成果物である。自分の判断で記録を書き足すな。対象は成果物であり、本節が置き先を定めた運用記録（案件・計画の記録と台帳）は含まない。
