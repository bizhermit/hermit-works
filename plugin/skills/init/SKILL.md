# hw:init

利用者環境に、本プラグインが前提とする規律の節と設定ファイルを展開する。初期設定済みの環境では、使用範囲と節ごとのリビジョンの変化を検知し、必要な節だけを再展開する。

## 手順

本手順の「プロジェクトルート」は、gitのリポジトリルートを指す。gitリポジトリでない場合は、セッションの作業ディレクトリを指す。

各手順は、自らが書いたものをその場で確かめてから次へ進む。確かめられなければ、以降の手順を行わず、満たされなかった内容と該当ファイル、およびそこまでに書き換えたファイルと内容を示して中断する。

1. 現状を確認する

    プロジェクトルートの`.hw/settings.json`を確認する。

    - 存在し、JSONとして読め、`version`・`scope`・`init`が揃っている場合: これを記録として扱い、本実行を再展開として進める旨を利用者に伝える。
    - それ以外の場合（存在しない、読めない、いずれかが欠けている）: 記録なしとして初回実行で進める。ファイルは手順6で書き直す。

2. バージョンを確認する

    `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`の`version`を読む。記録があれば記録の`version`と比較し、不一致は手順7で報告する。

    読んだ`version`が記録の`version`より古い場合は、記録を作った環境より古いプラグインで展開し直すことになるため、以降の手順を行わず、両方のバージョンを示して利用者の判断を仰ぐ。

3. 使用範囲を確認する

    `AskUserQuestion`で使用範囲を問う。

    - `project`: チーム標準としてリポジトリで共有
    - `local`: 個人利用でgit管理外

    再展開の場合は、記録されている`scope`を既定の選択肢として先頭に提示する。

4. 節を展開する

    展開する節・原稿・リビジョンは以下である。記録のキーは原稿のファイル名から拡張子を除いたものとする（以下、記録キー）。原稿の見出し行には`<!-- <記録キー> -->`の形でマーカーが埋め込まれている。

    |節|原稿|リビジョン|
    |--|--|--|
    | 憲章 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/charter.md` | 1 |
    | 参照データの扱い | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/reference.md` | 1 |
    | 裁定 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/ruling.md` | 1 |
    | 出力の表記 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/output-style.md` | 1 |
    | 記録の置き先 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/memory.md` | 1 |

    展開先は使用範囲で決まる。`project`はプロジェクトルートの`CLAUDE.md`、`local`はプロジェクトルートの`CLAUDE.local.md`であり、もう一方のファイルを「展開先でない方」と呼ぶ。

    展開先での節の同定は、見出しの文言ではなくマーカーで行う。節の範囲は、マーカーを含む`##`の見出しの行から、次の`##`以上の見出しの直前まで（無ければファイル末尾まで）とし、末尾の空行は範囲に含めない。原稿も末尾に空行を持たないため、原稿との比較はこの範囲どうしで行う。

    各節について、記録があり、記録の`scope`が手順3の結果と一致し、かつ記録の`init`の記録キーの値がリビジョンと一致する場合は、何もしない。それ以外の場合は、表の順に次で再展開する。

    1. 展開先と展開先でない方の両方から、その記録キーのマーカーを含む節をすべて除去する（複数あればすべて）。節の範囲に続く空行も併せて取り除く。除去した内容は手順7で報告するため控える。
    2. 展開先ファイルが無ければ、`# <ファイル名>`（`CLAUDE.md`なら`# CLAUDE.md`、`CLAUDE.local.md`なら`# CLAUDE.local.md`）の1行だけを書いて作成する。
    3. 1で展開先から除去した場合はその最初の位置へ、除去していなければファイル末尾へ、原稿を置く。前後の内容とは空行1行で区切り、ファイル末尾に空行を残さない。
    4. その節が展開先にちょうど1箇所あり、内容が原稿と一致することと、展開先でない方に同じマーカーが無いことを確かめる。マーカーの無い同じ文言の見出しがどちらかのファイルにあれば、利用者の節として残し、手順7で報告する。

    原稿は内容を変えて展開しない。利用者が節に入れていた変更は再展開で消えるため、除去した内容を報告し、必要な変更は利用者に入れ直してもらう。

5. `.gitignore`を整える

    gitリポジトリでなければ本手順を省略する。`.gitignore`が無ければ作成する。原稿は`${CLAUDE_PLUGIN_ROOT}/skills/init/assets/gitignore/`の`common`と、使用範囲が`project`の場合は`project`である（各行から空行を除く）。

    `.hw`ディレクトリに関する行は、ひとまとまりとして次の順で作り直す。展開の要否によらず毎回行う。

    1. `.gitignore`から、行頭が`.hw/`または`!.hw/`である行と、`.hw`のみの行をすべて抜き出し、最初に現れた位置を覚える。
    2. 抜き出した行のうち`!.hw/`で始まる行だけを残し、それ以外は捨てる。
    3. 使用範囲が`local`の場合は、残した行もすべて捨てる。
    4. 使用範囲が`project`の場合は、残した行に`project`の一覧の各行のうち無いものを加える。
    5. `common`のうち`.hw/`で始まる行、続いて残した行の順に並べ、1で覚えた位置へ戻す。抜き出した行が無ければ`.gitignore`の末尾へ置く。

    `common`のうち`.hw/`で始まらない行は、`.gitignore`に無ければ末尾へ追記する。

    次を確かめる。

    - `common`の各行が`.gitignore`に存在すること
    - `.hw/*`が、`!.hw/`で始まるどの行よりも前にあること
    - 使用範囲が`project`の場合、`project`の一覧の各行が`.gitignore`に存在すること
    - 使用範囲が`local`の場合、`!.hw/`で始まる行が`.gitignore`に存在しないこと

    `.gitignore`から消えた行と加わった行は手順7で報告する。

6. `.hw/settings.json`を書く

    `{"version": "<バージョン>", "scope": "<使用範囲>", "init": {"<記録キー>": <リビジョン>, ...}}`を書き込む。`version`は手順2で読んだ`plugin.json`の`version`、`scope`は手順3で確定した使用範囲、`init`は手順4の表の全節の記録キーとリビジョンである。ディレクトリが無ければ作成し、ファイルが既にあれば上書きする。

    書き込んだ内容が読み返せることを確かめる。

7. 報告する

    次を報告する。

    - 使用範囲と展開先、再展開した節と何もしなかった節、`.hw/settings.json`に記録した内容
    - 手順4で除去した内容。利用者の変更が含まれていた場合に入れ直せるよう、そのまま示す
    - 記録の`version`と`plugin.json`の`version`が不一致だった場合は、その旨と両方の値
    - 記録なしとして進めた場合は、その旨と理由
    - マーカーの無い同じ文言の見出しが残っている場合は、その旨とファイルパス
    - 手順5で`.gitignore`の行が増減した場合は、その内容
