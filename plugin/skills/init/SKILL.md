# hw:init

利用者環境に、本プラグインが前提とする規律の節と設定ファイルを展開する。初期設定済みの環境では、バージョンと使用範囲の変化を検知して再展開する。

## 手順

本手順の「プロジェクトルート」は、gitのリポジトリルートを指す。gitリポジトリでない場合は、セッションの作業ディレクトリを指す。

各手順は、自らが書いたものをその場で確かめてから次へ進む。確かめられなければ、以降の手順を行わず、満たされなかった内容と該当ファイル、およびそこまでに書き換えたファイルと内容を示して中断する。

1. 現状を確認する

    プロジェクトルートの`.hw/settings.json`を確認する。

    - 存在する場合: 記録されている`version`と`scope`を読み、本実行を再展開として進める旨を利用者に伝える。
    - 存在しない場合: 初回実行として進める。
    - 存在するがJSONとして読めない場合、または`version`か`scope`が欠けている場合: 記録として使えないため、存在しない場合と同じく初回実行として進める。ファイルは手順6で書き直す。

2. 使用範囲を確認する

    `AskUserQuestion`で使用範囲を問う。

    - `project`: チーム標準としてリポジトリで共有
    - `local`: 個人利用でgit管理外

    再展開の場合は、記録されている`scope`を既定の選択肢として先頭に提示する。

3. 差分を確認する

    初回実行の場合は本手順を省略する。

    再展開の場合、`${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`の`version`を読み、記録と比較する。`version`が一致し、かつ`scope`も手順2の結果と一致する場合は、手順4から手順6を省略して手順7へ進む。このとき展開先が記録後に変更されていても、利用者が運用に合わせて行った変更として許容し、展開も検証も行わない。

4. 節を展開する

    展開する節と原稿は以下であり、表の順に展開する。

    |節|原稿|
    |--|--|
    | 憲章 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/charter.md` |
    | 参照データの扱い | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/reference.md` |
    | 裁定 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/ruling.md` |
    | 出力の表記 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/output-style.md` |
    | 記録の置き先 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/memory.md` |

    展開先は、節ごとに次で判定する。

    - `project`の場合: プロジェクトルートの`CLAUDE.md`
    - `local`の場合: プロジェクトルートの`CLAUDE.local.md`。ただし`CLAUDE.md`にその節がすでにあり、かつ記録されている使用範囲が`project`でない場合（初回実行で記録が無い場合を含む）は、その節を利用者が意図して配置したものとして`CLAUDE.md`を展開先とする

    この判定により、展開先が`CLAUDE.md`の節と`CLAUDE.local.md`の節に分かれることがある。使用範囲が`local`でありながら`CLAUDE.md`に置かれていた節は、利用者がその節だけ共有すると判断した結果であり、配置を揃えず維持する。以降の手順も節ごとに扱い、他の節の展開先を根拠にしない。

    節の範囲は、見出し`## <節名>`の行から、次の`##`以上の見出しの直前まで（無ければファイル末尾まで）とし、末尾の空行は範囲に含めない。原稿も末尾に空行を持たないため、原稿との比較はこの範囲どうしで行う。各節について、次の順で行う。

    1. 展開先ファイルが無ければ作成する。
    2. 展開先に同じ見出しが2箇所以上ある場合は、どれが正本か判断できないため、その節は展開せずに次の節へ進み、ファイルパスと該当行を示して利用者の判断を仰ぐ。展開できなかった節として控える。
    3. 展開先に見出しが無ければ、ファイル末尾へ空行1行を挟んで原稿を追記する。
    4. 展開先に見出しがあれば、その節の範囲と原稿を比較する。一致していれば何もしない。相違があれば、利用者が手を入れたものとして現状を維持し、上書きせず、差異があることを手順7で報告する。
    5. 展開先でない方のファイルに同じ見出しの節があれば、使用範囲が記録から変わったか（`project`から`local`、またはその逆）で扱いを分ける。変わった場合は、その範囲と原稿を比較し、一致していれば前回の展開物として除去する。相違があれば、利用者が手を入れたものとして除去せず、そのまま残す。変わっていない場合は、その節は前回の展開物ではないため、比較の結果によらず除去しない。除去するときは、節の範囲に続く空行も併せて取り除き、跡に空行だけが残らないようにする。除去しなかった節は、同じ節が両方のファイルに残ることとあわせて手順7で報告する。
    6. その節が、その節について判定した展開先にちょうど1箇所存在することを確かめる。4で内容を維持した場合を除き、その内容が原稿と一致することも確かめる。5で除去した場合は、展開先でない方のファイルにその節が無いことを確かめる。

    原稿は内容を変えて展開しない。除去した残置物は手順7で報告する。

    既にある節を原稿で上書きすること、および残したものを除去することは、利用者の指示を受けたときに限る。本実行では行わず、報告に留める。指示を受けて上書き・除去する場合は、その節に加えられていた変更が失われること、必要な変更は利用者の手で入れ直すことを併せて伝える。

5. `.gitignore`を整える

    gitリポジトリでなければ本手順を省略する。`.gitignore`が無ければ作成する。原稿は`${CLAUDE_PLUGIN_ROOT}/skills/init/assets/gitignore/`の`common`と、使用範囲に応じた`project`または`local`である（各行から空行を除く）。

    `.hw`に関する行は、ひとまとまりとして次の順で作り直す。記録の有無や使用範囲の変更の有無によらず毎回行う。

    1. `.gitignore`から、行頭が`.hw`または`!.hw`である行をすべて抜き出し、最初に現れた位置を覚える。
    2. 抜き出した行のうち`!.hw`で始まる行だけを残し、それ以外は捨てる。
    3. 使用範囲が`local`の場合は、残した行もすべて捨てる。
    4. 使用範囲が`project`の場合は、残した行に`project`の一覧の各行のうち無いものを加える。
    5. `common`のうち`.hw`で始まる行、続いて残した行の順に並べ、1で覚えた位置へ戻す。抜き出した行が無ければ`.gitignore`の末尾へ置く。

    `common`のうち`.hw`で始まらない行は、`.gitignore`に無ければ末尾へ追記する。

    次を確かめる。

    - `common`の各行が`.gitignore`に存在すること
    - `.hw/*`が、`!.hw`で始まるどの行よりも前にあること
    - 使用範囲が`project`の場合、`project`の一覧の各行が`.gitignore`に存在すること
    - 使用範囲が`local`の場合、`!.hw`で始まる行が`.gitignore`に存在しないこと

    `.gitignore`から消えた行と加わった行は手順7で報告する。

6. `.hw/settings.json`を書く

    手順4-2で展開できなかった節があれば、本手順を行わない。展開が済んでいない状態を展開済みとして記録すると、次の実行が手順3で省略され、その節が点検されなくなるためである。

    `{"version": "<バージョン>", "scope": "<使用範囲（project または local）>"}`を書き込む。`version`は`${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`の`version`（手順3で読んでいなければここで読む）、`scope`は手順2で確定した使用範囲である。ディレクトリが無ければ作成し、ファイルが既にあれば上書きする。

    書き込んだ内容が読み返せることを確かめる。

7. 報告する

    次を報告する。

    - 展開先と展開した節、`.hw/settings.json`に記録した内容（バージョン・使用範囲）
    - 手順1で`.hw/settings.json`を読めずに初回実行として進めた場合は、その旨と理由。あわせて、直前の使用範囲が分からないため、手順4の展開先の移動と手順4-5の残置物の除去が行われないこと
    - 手順3で省略した場合は、バージョンと使用範囲に変化がないため再展開を行っていないこと（展開先の内容は確認していない）
    - 手順6を行わなかった場合は、展開できなかった節があるため記録していないこと。該当する節と、解消するために必要なこと
    - 手順4-4・手順4-5で上書きも除去も行わなかった節は、節名・該当するファイルパス・維持した理由（原稿との相違、または使用範囲が変わっていないこと）と、同じ節が両方のファイルに残る場合はその旨。上書きや除去を望む場合は指示を求めること
    - 手順4で残置物を除去した場合と、手順5で`.gitignore`の行が増減した場合は、その内容
