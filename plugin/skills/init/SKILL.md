# hw:init

利用者環境に、本プラグインが前提とする規律の節と設定ファイルを展開する。初期設定済みの環境では、バージョンと使用範囲の変化を検知して再展開する。

## 手順

本手順の「プロジェクトルート」は、gitのリポジトリルートを指す。gitリポジトリでない場合は、セッションの作業ディレクトリを指す。

1. 現状を確認する

    プロジェクトルートの`.hw/settings.json`を確認する。

    - 存在する場合: 記録されている`version`と`scope`を読み、本実行を再展開として進める旨を利用者に伝える。
    - 存在しない場合: 初回実行として進める。
    - 存在するがJSONとして読めない場合、または`version`か`scope`が欠けている場合: 処理を中断し、ファイルパスと理由を利用者に伝える。

2. 使用範囲を確認する

    `AskUserQuestion`で使用範囲を問う。

    - `project`: チーム標準としてリポジトリで共有
    - `local`: 個人利用でgit管理外

    再展開の場合は、記録されている`scope`を既定の選択肢として先頭に提示する。

3. `.hw/conventions.md`を用意する

    無ければ原稿`${CLAUDE_PLUGIN_ROOT}/skills/init/assets/conventions.md`をそのまま書き込んで作成する。既にあれば内容を変更しない（利用者の判断記録を蓄積するファイルであり、再展開で上書きしない）。ディレクトリが無ければ作成する。

4. 差分を確認する

    初回実行の場合は本手順を省略する。

    再展開の場合、`${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`の`version`を読み、記録と比較する。`version`が一致し、かつ`scope`も手順2の結果と一致する場合は、手順5から手順8を省略して手順9へ進む。このとき展開先が記録後に変更されていても、利用者が運用に合わせて行った変更として許容し、展開も検証も行わない。

5. 節を展開する

    展開する節と原稿は以下であり、表の順に展開する。

    |節|原稿|
    |--|--|
    | 憲章 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/charter.md` |
    | 参照データの扱い | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/reference.md` |
    | 裁定 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/ruling.md` |
    | 出力の表記 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/output-style.md` |
    | 記録の置き先 | `${CLAUDE_PLUGIN_ROOT}/skills/init/assets/memory.md` |

    展開先は、節ごとに次で判定する。

    - `project`の場合: プロジェクトルートの`CLAUDE.md`
    - `local`の場合: プロジェクトルートの`CLAUDE.local.md`。ただし`CLAUDE.md`にその節がすでにあり、かつ記録されている使用範囲が`project`でない場合（初回実行で記録が無い場合を含む）は、その節を利用者が意図して配置したものとして`CLAUDE.md`を展開先とする

    この判定により、展開先が`CLAUDE.md`の節と`CLAUDE.local.md`の節に分かれることがある。使用範囲が`local`でありながら`CLAUDE.md`に置かれていた節は、利用者がその節だけ共有すると判断した結果であり、配置を揃えず維持する。以降の手順も節ごとに扱い、他の節の展開先を根拠にしない。

    節の範囲は、見出し`## <節名>`の行から、次の`##`以上の見出しの直前まで（無ければファイル末尾まで）とし、末尾の空行は範囲に含めない。原稿も末尾に空行を持たないため、原稿との比較はこの範囲どうしで行う。各節について、次の順で行う。

    1. 展開先ファイルが無ければ作成する。
    2. 展開先に同じ見出しが2箇所以上ある場合は、どれが正本か判断できないため展開せず、ファイルパスと該当行を示して利用者の判断を仰ぐ。
    3. 展開先に見出しが無ければ、ファイル末尾へ空行1行を挟んで原稿を追記する。
    4. 展開先に見出しがあれば、その節の範囲と原稿を比較する。一致していれば何もしない。相違があれば、利用者が手を入れたものとして現状を維持し、上書きせず、差異があることを手順9で報告する。
    5. 展開先でない方のファイルに同じ見出しの節があれば、使用範囲が記録から変わったか（`project`から`local`、またはその逆）で扱いを分ける。変わった場合は、その範囲と原稿を比較し、一致していれば前回の展開物として除去する。相違があれば、利用者が手を入れたものとして除去せず、そのまま残す。変わっていない場合は、その節は前回の展開物ではないため、比較の結果によらず除去しない。除去するときは、節の範囲に続く空行も併せて取り除き、跡に空行だけが残らないようにする。除去しなかった節は、同じ節が両方のファイルに残ることとあわせて手順9で報告する。

    原稿は内容を変えて展開しない。除去した残置物は手順9で報告する。

    既にある節を原稿で上書きすること、および残したものを除去することは、利用者の指示を受けたときに限る。本実行では行わず、報告に留める。指示を受けて上書き・除去する場合は、その節に加えられていた変更が失われること、必要な変更は利用者の手で入れ直すことを併せて伝える。

6. `.gitignore`を整える

    gitリポジトリでなければ本手順を省略する。`.gitignore`が無ければ作成する。原稿は`${CLAUDE_PLUGIN_ROOT}/skills/init/assets/gitignore/`の`common`と、使用範囲に応じた`project`または`local`である（各行から空行を除く）。

    `.hw`に関する行は、ひとまとまりとして次の順で作り直す。記録の有無や使用範囲の変更の有無によらず毎回行う。

    1. `.gitignore`から、行頭が`.hw`または`!.hw`である行をすべて抜き出し、最初に現れた位置を覚える。
    2. 抜き出した行のうち`!.hw`で始まる行だけを残し、それ以外は捨てる。
    3. 使用範囲が`local`の場合は、残した行もすべて捨てる。
    4. 使用範囲が`project`の場合は、残した行に`project`の一覧の各行のうち無いものを加える。
    5. `common`のうち`.hw`で始まる行、続いて残した行の順に並べ、1で覚えた位置へ戻す。抜き出した行が無ければ`.gitignore`の末尾へ置く。

    `common`のうち`.hw`で始まらない行は、`.gitignore`に無ければ末尾へ追記する。

    `.gitignore`から消えた行と加わった行は手順9で報告する。

7. 検証する

    手順5の各節について、節ごとに次を確認する。他の節の展開先は判定に用いない。

    - その節が、その節について判定した展開先にちょうど1箇所存在すること
    - その節の内容が原稿と一致すること（diffで確認する）。ただし手順5-4で利用者の変更を維持した節は対象外とする
    - その節について展開先でない方のファイルに、その節が無いこと。ただし手順5-5で除去しなかった節は対象外とする

    あわせて次を確認する。

    - `.hw/conventions.md`が存在すること
    - 手順6を行った場合、`common`の各行が`.gitignore`に存在すること
    - 手順6を行った場合、`.hw/*`が`!.hw`で始まるどの行よりも前にあること
    - 手順6を行い、使用範囲が`project`の場合、`project`の一覧の各行が`.gitignore`に存在すること
    - 手順6を行い、使用範囲が`local`の場合、`!.hw`で始まる行が`.gitignore`に存在しないこと

    満たされない項目があれば、手順8を行わず、満たされなかった項目と該当ファイルを示して中断する。

8. `.hw/settings.json`を書く

    `{"version": "<バージョン>", "scope": "<使用範囲（project または local）>"}`を書き込む。`version`は`${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`の`version`（手順4で読んでいなければここで読む）、`scope`は手順2で確定した使用範囲である。ディレクトリが無ければ作成し、ファイルが既にあれば上書きする。

9. 報告する

    次を報告する。

    - 展開先と展開した節、`.hw/settings.json`に記録した内容（バージョン・使用範囲）
    - 手順4で省略した場合は、バージョンと使用範囲に変化がないため再展開を行っていないこと（展開先の内容は確認していない）
    - 手順5-4・手順5-5で上書きも除去も行わなかった節は、節名・該当するファイルパス・維持した理由（原稿との相違、または使用範囲が変わっていないこと）と、同じ節が両方のファイルに残る場合はその旨。上書きや除去を望む場合は指示を求めること
    - 手順3で`.hw/conventions.md`を作成した場合はその旨、手順5で残置物を除去した場合と手順6で`.gitignore`の行が増減した場合はその内容
