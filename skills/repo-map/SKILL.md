# リポジトリ構成マップの作成・更新

`.hw/repo-map.md` は hermit-works 組織の全エージェントが対象プロジェクトを特定するための共有マップ。以下の手順で作成・更新する。

## 手順

以下はいずれも判断を伴わない機械的な調査・整形作業のため、実行主体はこのスキルを使っている
エージェント自身（呼び出し元が直接実行する）とする。専任の担当エージェントへの委任は不要。

1. **プロジェクトの検出**（実行主体: 呼び出し元が直接実行する）: リポジトリ直下および慣習的な場所（`apps/`, `packages/`, `services/`, `projects/` 等）を走査し、ビルド定義（package.json, pyproject.toml, go.mod, *.csproj, Cargo.toml, build.gradle 等）を持つディレクトリをプロジェクトとして列挙する。node_modules 等の依存ディレクトリは除外する。

2. **プロジェクトごとの情報収集**（実行主体: 呼び出し元が直接実行する）: 各プロジェクトについて以下を調べる。
   - 種別（Webフロント / API / バッチ / モバイル / デスクトップ / 共有ライブラリ）
   - 言語・フレームワーク・主要な依存
   - ビルド・テスト・起動コマンド（scripts や Makefile、README から）
   - 他プロジェクトへの依存（API 呼び出し・共有ライブラリ参照）

3. **マップの作成**（実行主体: 呼び出し元が直接実行する）: `.hw/repo-map.md` に以下の形式で書く。手順2で検出した種別に該当プロジェクトが1つも無い場合、その種別を主担当とする hermit-works グループ・エージェントを「関連性の低いグループ（参考）」節に列挙してよい（任意節。該当なし・不要なら省略可）。
   ```markdown
   # リポジトリ構成マップ
   最終更新: <日付>

   ## プロジェクト一覧
   | プロジェクト | パス | 種別 | 技術スタック | 概要 |
   |---|---|---|---|---|

   ## 依存関係
   （プロジェクト間の依存を箇条書きまたは mermaid 図で）

   ## 共通コマンド
   （各プロジェクトのビルド・テスト・起動コマンド）

   ## 関連性の低いグループ（参考）
   （検出済み種別に存在しない種別のみ。例: モバイルプロジェクトが無い場合 eng-mobile。将来の追加可能性を推測して書かない）
   ```

4. **更新の場合**（実行主体: 呼び出し元が直接実行する）: 既存マップとの差分（追加・削除・変更されたプロジェクト）を明記して報告する。

## 注意
- 推測で書かない。ビルド定義や README で確認できた事実のみを記載する。
- 不明な点は「未確認」と明記する。
