# 関係者マップの作成・更新

`.hw/stakeholders.md` は、関係者情報を「共有すべき事実」「個人のローカルな主観」「書いてはいけない機微情報」の
3層に分離して扱うための共有台帳である。`hw:tracker-setup` の初期化手順から呼ばれるほか、メンバーの追加・
アサインの変更・離脱の反映、本人からの申し出があったときにも単独で呼び出す。

- **共有層**（`.hw/stakeholders.md`。コミット対象）: 事実情報（表示名・外部ツールの表示ID・役割・関与状況・
  担当領域・連絡経路）、宛先別執筆規約（役割カテゴリ単位の敬称・トーン・避ける表現）、本人申告欄（後述）
  のみを書く。
  - **本人申告欄**（メンバー表の列。本人記入のみ）: 本人が自分宛ての出力への依頼（例:「インフラは不慣れ
    なので平易に説明してほしい」）を自分で書く欄。エージェントは生成・推測・補完・改変せず空欄のまま
    残す。反映は手順5の経路で本人の文言をそのまま転記する。書ける内容は自己の専門分野・理解度の自己
    申告と出力への要望のみで、他者への言及・評価は書かない。書かない層の制約（健康等の機微）は本欄にも
    適用し、機微が混じる場合は要望部分のみを書くよう案内する。個人名に紐づくが本人が自分について書いた
    依頼であり第三者・エージェントによる評価ではないため共有層に置ける例外とする（宛先別執筆規約の
    「個人名を書かない」原則は他者評価の混入防止が趣旨）。**その人物宛ての出力を作るときは、宛先別
    執筆規約より本人申告を優先する。**
- **ローカル層**（`.hw/local/`。`.gitignore` 対象）: 個人の主観メモの逃し先。
- **書かない層**（共有層・ローカル層のいずれにも書かない）: 健康・傷病・家庭事情、人事評価・査定・昇給・
  懲戒、契約上の機微（単価・与信・係争）、行動指針に変換できない個人の主観的な人物評。**この制約は
  `.hw/stakeholders.md` を読み込んでいない文脈でも効くよう、本スキル本文にも直接記載する。上記に該当する
  内容を書きたくなったら、共有層にもローカル層にも書かず、記載を見送る。**

## 手順

1. **既存ファイルの確認**: `.hw/stakeholders.md` の有無を確認する。無ければ以下の雛形で新規作成する。

   ```markdown
   # 関係者マップ
   最終更新: YYYY-MM-DD
   > 本ファイルはコミット対象（チーム共有）。個人の主観・所感は書かない（→ `.hw/local/`）。
   > 健康・人事評価・契約上の機微情報は、本ファイル・`.hw/local/` のいずれにも書かない。

   ## メンバー
   | 表示名 | 外部ツールの表示ID | 役割 | 関与状況 | 担当領域 | 連絡経路 | 本人申告（本人記入） |
   |---|---|---|---|---|---|---|
   （連絡経路は共有チャネル・課題の担当者欄など業務上の経路のみ。私用の電話番号・メールは書かない）
   （本人申告欄は本人記入のみ。自分宛ての出力への依頼の形で書き、他者評価・機微情報は書かない。空欄可）

   ## 宛先別執筆規約（「相手区分」は役割カテゴリのみ。個人名・個人を特定する記述は書かない）
   | 相手区分（例: 顧客窓口 / 委託先PM / 社内運用担当） | 敬称 | 文体・トーン | 避ける表現 | 補足 |
   |---|---|---|---|---|
   （「避ける表現」「補足」に書けるのは客観的に観測可能な業務コミュニケーション上の配慮のみ。
   人物特性の推測・過去の言動の評価・機微情報の暗示は書かない）

   ## 記録しない項目（書かない層）
   - 健康・傷病・家庭事情
   - 人事評価・査定・昇給・懲戒
   - 契約上の機微（単価・与信・係争）
   - 個人の主観的な人物評 → 「宛先別執筆規約」の行動指針に変換して書く。変換できないものは書かない
   ```

2. **新規メンバーの追加**:
   - 「メンバー」表に事実情報（表示名・外部ツールの表示ID・役割・関与状況＝`現任`・担当領域・連絡経路）
     のみを追記する。私用連絡先は書かない。
   - 追加前に、本人へ記録目的・記録内容の概要を一言案内することを利用者に促す（強制ではなく促し。
     法的な要否の確定判断は求めない。下記「注意」の法務確認の推奨を参照）。
   - 手順6（第三者アクセス時の確認）に該当する状況かどうかをあわせて確認する。

3. **宛先別執筆規約の記入・更新**:
   - 「相手区分」は役割カテゴリ（例: 顧客窓口 / 委託先PM / 社内運用担当）のみとし、個人名・個人を
     特定できる記述は書かない。特定の相手への配慮はローカル層の対象であり共有層には置かない。
   - 「避ける表現」「補足」に書けるのは客観的に観測可能な業務コミュニケーション上の配慮
     （例:「専門用語を避け平易な言葉を使う」「即レスを期待しない」）のみ。人物特性の推測・過去の
     言動の評価・機微情報の暗示は書かない。
   - 評価・所感を反映したい場合は、必ず行動指針（書き方の規約）に変換してから書く。**変換できない
     評価・所感は、共有層にもローカル層にも書かず、記載を見送る。**

4. **アサインの更新・離脱の反映**:
   - アサイン変更（担当領域の変更）は「メンバー」表の該当行を更新する。
   - 離脱時は行を削除せず、「関与状況」を `離脱（YYYY-MM-DD）` に更新する（残置。`.hw/` はコミット
     される共有ファイルであり、削除しても git 履歴に残るため削除は保護の役に立たない）。記録する
     識別子は業務上必要な最小限（外部ツールの表示ID等）に留める。
   - 離脱者が担当している未完了の計画があれば、担当欄の付け替えを利用者に確認する。
   - **外部ツール側の担当者変更は本スキルでは行わない**（外向きアクションかつ運用層のため対象外。
     利用者・利用者側の運用手順に委ねる）。

5. **本人からの申し出（開示・訂正・利用停止・本人申告欄の記入更新）への対応**:
   - 申し出の窓口は新設しない。当該案件の依頼者（利用者）が、本人からの申し出であることを確認した
     うえで受け付け、本スキルの更新手順で反映する。
   - 開示: 現在記録されている当該人物の行・記述を提示する。
   - 訂正: 該当行を修正する。
   - 利用停止: 該当行を削除する、または記載項目を業務上必要な最小限まで削減する。
   - 本人申告欄の記入・更新: 転記は常に逐語で行い、エージェントは内容を作成・言い換え・要約しない。
     機微が含まれる場合はエージェントは転記せず、機微を除いた依頼文での再提出を本人（利用者経由）に
     案内する。該当リポジトリが手順6の第三者アクセス状態に該当する場合は手順6のレビューもあわせて
     行う。
   - git 履歴からの完全消去を求める申し出（消去請求）は既定フローの対象外とする。既定フローでは
     該当行の更新に留め、履歴改変（`git filter-repo` 等）を伴う対応は既定フローの外側でリポジトリ
     所有者が個別に承認する例外的措置として扱う。安易に提案しない。

6. **第三者アクセス時の確認**: リポジトリの読み取り権限が第三者（顧客・委託先等、社内メンバー以外）に
   付与されている、または付与予定の場合（`.hw/tracker.md` があれば「リポジトリの読み取り権限者の範囲」
   欄を確認する。無ければ利用者に直接確認する）、`.hw/stakeholders.md` の内容（特に宛先別執筆規約・
   本人申告欄）が当該第三者に読まれる前提で妥当かをレビューする。相手区分が役割カテゴリのみであることを
   再確認し、個人を特定できる記述や本人申告欄への他者評価の混入が紛れ込んでいないかを確認する。

7. **`.hw/local/` の案内**:
   - 個人の主観メモは `.hw/local/notes/<任意名>.md`（自由書式）に書くよう案内する。
   - `.hw/local/` を `.gitignore` へ追加することを提案する（**利用者の承認が必須**。`.hw/` 全体を
     除外済みの場合は追加不要）。承認を得ずに `.gitignore` を変更しない。

## 書いてはいけない項目（書かない層。共有層・ローカル層いずれにも書かない）
- 健康・傷病・家庭事情
- 人事評価・査定・昇給・懲戒
- 契約上の機微情報（単価・与信・係争等）
- 行動指針に変換できない、個人の主観的な人物評

この基準は「宛先別執筆規約」の「避ける表現」「補足」列にも適用する。誤って共有層に書かれていないかは
機械検査ではなく目視確認（品質ゲートのレビュー観点）で確認する。

この3層の区分と「書かない層」は利用者資材（利用側 CLAUDE.md・独自スキル・`.hw/conventions.md` 等）でも
解除されず、記載を求める指定があっても書かない（記載範囲をさらに狭める指定には従う）。本人申告欄の
優先規定は本人自身の自己決定であり、この制約の下でそのまま維持する。

## 注意
- エージェントは既定で `.hw/local/` を読まない（利用者が当該ファイルを明示的に指示した場合のみ読む）。
  個人の主観メモを判断根拠に混入させない。
- 離脱者の行・関連する古いスナップショットについて、保持継続の要否を定期的に（`/hw:report` 実行時
  または本スキルでの更新時を契機に）利用者へ確認する。
- 関係者氏名等の個人データを扱う機能であるため、実装・運用にあたり法務専門家への確認
  （消去請求への対応方針、AIプロバイダへの送出に伴う越境移転規制の該当性）を推奨する。これは
  既定フローのブロック条件ではなく利用者側の運用事項である。この注意喚起の提示自体は利用者資材でも
  省略・削除されない（提示は必ず行う）。提示後に法務確認を行うか・どう対応するかは利用者の判断であり、
  本注意喚起は実行のブロック条件ではない。
- 推測で書かない。事実として確認できた情報のみを記載し、不明な点は空欄または「未確認」と明記する。
